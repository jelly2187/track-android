# Track 使用指南

[返回首页](../README.md) · [下载最新版](https://github.com/jelly2187/track-android/releases/latest)

## 创建与记录

在首页点击加号创建习惯。「完成 / 未完成」适合每天确认一次的行动；「累计目标」可设置目标、单位与每次快捷增加量。

选择每周打卡日，按需添加颜色分组与提醒。计数达到目标后自动完成；也可明确确认当天未完成、撤销或补记历史记录。详情页展示日历、完成率与连续坚持情况，休息日不打断连续记录。

## 提醒

首次启用提醒时允许通知，并在设置中检查「准时提醒」权限。提醒计划可以与打卡计划不同；只有当天应打卡且未确认的习惯才会提醒。

默认每15分钟追提醒，可改为“不重复”、30 或 60 分钟。23:00—07:00 静音期间暂停重复唤醒；你明确设置在该时段的某个提醒仍会静默显示。当日完成或确认未完成后停止；当天通知在午夜由系统到期清除，不追提醒前一天。

没有开启提醒、没有有效提醒计划或通知权限关闭时，不安排提醒唤醒。每周计划直接等待下一个提醒日，不按天唤醒轮询。

部分安卓系统允许单独划掉常驻通知，Track 会保留待办，在下一次提醒时重新显示。关闭通知、强行停止、勿扰与后台省电限制会影响提醒；可在设置中发送测试通知并检查系统权限。强行停止后需重新打开应用恢复调度。

## 桌面小组件

小组件会同步 App 内的打卡、撤销和历史记录修改。列表中的打卡/累计按钮可直接记录当天进度，不需要打开 App 后才更新状态。

长按桌面空白处，进入小组件列表并选择 Track：

- **今日习惯**：查看多个习惯状态，直接打卡或快捷累计，可筛选颜色分组。
- **坚持日历**：选择一个习惯，查看近期28天记录和连续坚持次数。

支持多个独立实例与尺寸调整；点击习惯名称打开详情，齿轮用于重新配置。

## 备份与恢复

在设置中导出完整 JSON 备份，包含习惯、分组、提醒、计划历史和记录。恢复会替换当前手机数据，请先备份。桌面小组件实例不随备份迁移，需要重新选择习惯或分组。

记录只保存在本机，没有账号或云同步。卸载前请先导出备份。

## 更新

启动时自动检查 GitHub Releases，也可在设置中手动检查或关闭启动检查。发现新版后，点击“下载更新”在 App 内下载；校验大小、SHA-256、包名、版本和签名后，显示“安装更新”。首次需要在系统设置中允许 Track 安装应用，返回后再次点击安装，最终由系统确认。

下载中点击“后台下载”或关闭弹窗后，可继续打卡和查看统计，后续进度及下载完成都不会自动重新弹窗。到设置中点击“查看下载进度”或“查看已下载更新”即可继续操作；也可以取消下载。后台下载依赖应用进程，系统终止进程时可能中断；再次下载会检查并复用已完整下载且校验通过的缓存。

点击“稍后”或关闭更新提示后，该发布版本不再自动弹出，重新打开应用仍有效；手动检查可以再次查看。安装前若发现缓存损坏，会拒绝安装并允许重新下载。

0.1.4 / 0.1.5 使用浏览器下载。请先通过其现有入口或本仓库发布页覆盖安装 0.1.6，此后恢复应用内更新；无需卸载旧版。安装时保留系统安全检测和确认流程。

断网或 GitHub 暂时不可达不会影响打卡。默认更新地址：

```text
https://github.com/jelly2187/track-android/releases/latest/download/latest.json
```

0.1.0 / 0.1.1 使用旧发布渠道，请先从本仓库手动覆盖安装 0.1.2 或更新版本。不要卸载旧版，保留相同签名的覆盖安装可保留记录。已保存的旧渠道地址会迁移，自定义更新地址保持不变。
