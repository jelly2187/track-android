# 安装风险提示：检查结果与处理方式

[返回首页](../README.md) · [隐私与权限](../PRIVACY.md) · [下载新版](https://github.com/jelly2187/track-android/releases/latest)

检查日期：2026 年 11 月 5 日。检查对象为已发布的 Track 0.1.3 源码与 APK，以及改进后的 0.1.4。

## 如何理解提示

“恶意占用系统资源、自动捆绑安装、自动修改系统配置、频繁发送骚扰信息”等通用描述，无法单独指明某一条代码或确认属于误报。当前还没有取得此次手机检测的完整引擎名称、风险编号或行为证据，也尚未在该手机上完成新版检测复测。

OPPO 官方白皮书说明，安装判断同时使用静态、动态、业务与信誉特征，并结合多家检测引擎。因此，减少权限和后台行为能改善应用设计，但不能保证每个品牌、每个安全数据库立即撤销提示。[OPPO 智能护盾应用安全治理白皮书，第 21—26 页](https://privacy.oppo.com/privacy-center/pdf/OPPO%E6%99%BA%E8%83%BD%E6%8A%A4%E7%9B%BE%E5%BA%94%E7%94%A8%E5%AE%89%E5%85%A8%E6%B2%BB%E7%90%86%E7%99%BD%E7%9A%AE%E4%B9%A6%EF%BC%882023%EF%BC%89.pdf)

## 代码与安装包中检查到的情况

| 提示涉及的能力 | 检查结果 | 0.1.4 的改进 |
| --- | --- | --- |
| 安装应用 | 旧版声明了 `REQUEST_INSTALL_PACKAGES`，用于用户主动确认的本应用更新；未发现静默安装或携带其他 APK。 | 移除该权限、APK 下载器、文件分享 Provider 和系统安装入口。保留版本检查，用户点击后打开浏览器。 |
| 后台资源 | 旧版有每 30 分钟的全局轮询，即使未开启提醒也会运行；提醒规划还会默认安排午夜唤醒。 | 取消旧轮询，直接安排下一个有效提醒时间。无有效计划或通知权限关闭时取消提醒唤醒；夜间暂停重复唤醒。 |
| 前台常驻 | WorkManager 依赖合并了前台服务权限与组件，但 Track 未使用前台任务。 | 从最终清单中移除不使用的前台服务权限与组件，保留小组件所需的短时系统任务能力。 |
| 系统配置 | 未发现 `WRITE_SETTINGS`、`WRITE_SECURE_SETTINGS` 权限或写入系统设置的调用。设置按钮只打开系统页面，等待用户操作。 | 系统事件接收器设为非导出；明确说明相关设置由用户确认。 |
| 消息与通知 | 无短信或通讯录权限。通知来自用户开启的习惯提醒，多个习惯汇总在同一通知中；没有营销推送 SDK。 | 增加“不重复”选项，保留 15/30/60 分钟设置；完成或确认未完成后停止当天跟进。 |
| 网络 | 未接入广告或统计 SDK；应用联网入口为 HTTPS 更新描述请求。 | 明确禁止明文网络，新增可离线查看的隐私与权限说明。 |

`REQUEST_INSTALL_PACKAGES` 本身不等同于恶意行为，但属于需要谨慎使用的能力。Google Play 将其列为受限制权限；这也是减少习惯工具安装权限的依据，而不是对 OPPO 某次命中规则的断言。[Google Play 权限说明](https://support.google.com/googleplay/android-developer/answer/12085295?hl=zh-Hans)

## 验证范围

- 自动测试覆盖权限清单、更新仅访问描述文件、下载入口只打开 HTTPS 网页、无提醒时不安排唤醒、撤销通知权限后取消唤醒、静音与每周计划、关闭重复提醒，以及已有小组件同步功能。
- 对 123 个实际解析的运行时依赖版本进行 OSV 已知漏洞查询，查询时没有匹配记录。该结果仅涉及已收录的依赖漏洞，不是病毒查杀结果，不保证不存在未披露问题。[OSV 查询 API](https://google.github.io/osv.dev/post-v1-querybatch/)
- `scripts/AuditRelease.ps1` 直接检查编译后的 APK：权限白名单、调试标记、签名完整性、明文网络设置、内嵌 APK/JAR 等载荷，并生成 SHA-256、MD5 与复核材料。
- 安装包保持原包名及签名，升级请覆盖安装。保留系统的文件检测、签名检查与安装确认。

本轮没有上传 APK 到第三方查杀服务，没有获得 OPPO/其他厂商安全认证，也没有执行手机上的恶意行为沙箱检测。不能把单元测试、依赖查询或包结构检查写成“杀毒通过”。

## 新版仍有提示时

1. 核对下载来源为本项目的 GitHub Releases，记录版本与 APK SHA-256；不要把不同来源的重打包文件混在同一次反馈中。
2. 保留完整提示截图，记录风险名称、检测引擎、手机系统版本、安装来源及复现步骤。通用风险分类与具体病毒名称要分别记录。
3. 使用该品牌官方开发者支持或安全检测服务申请复核。OPPO 官方社区处理此类问题时要求应用 ID、应用名称、版本与文件 MD5；当前具体入口和其他材料以厂商要求为准。[OPPO 官方处理示例](https://open.oppomobile.com/bbs/forum.php?mod=viewthread&tid=3569)、[OPPO 隐私安全检测服务](https://open.oppomobile.com/new/introduction?page_name=audit-open)
4. 只有详情明确指向腾讯引擎时，再使用[腾讯手机管家申诉入口](https://m.qq.com/complaint/)；不能推定所有品牌的判断都来自同一引擎。[腾讯移动安全的处理说明](https://cloud.tencent.com/developer/article/1133371)

每次构建的 `artifacts/reports/版本号/VENDOR_REVIEW.md` 会提供包名、版本、APK 地址、MD5、SHA-256 和改进说明，方便针对实际样本复核。复核申请需要相应账号和手机上的证据；项目不会未经确认代用户发送申诉或上传资料。

面向更多手机长期分发时，应持续使用同一签名和固定发布渠道，并按目标应用商店的身份、隐私与发布要求提交审核。GitHub 开源和个人签名本身不等于手机厂商认证，也没有一次改包就能消除所有品牌风险提示的通用方法。
